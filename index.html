🔌 Le Jeu de l'API

Bienvenue ! Une API (Interface de Programmation d'Application), c'est un mot qui fait peur… mais le concept est simple.

Imaginez que vous allez au restaurant. Vous ne rentrez pas en cuisine préparer vous-même votre plat : vous passez par un serveur qui transmet votre commande, puis vous rapporte le résultat.

Une API fonctionne exactement pareil, mais entre deux logiciels (une application et un serveur informatique).

Ce jeu va vous le faire vivre en 4 étapes :

  • 🍽️ Chapitre 1 — Le restaurant (comprendre le principe)
  • 🚨 Chapitre 2 — Quand ça se passe mal (les erreurs)
  • 🧠 Chapitre 3 — Le quiz (vérifier vos connaissances)
  • 🎮 Chapitre 4 — Le simulateur (manipuler une API vous-même)

Mais... que se passe-t-il si le plat n'existe pas, ou si la cuisine prend feu ? ⬇️

📋 Récapitulatif du Chapitre 1

Voici la correspondance entre le restaurant et l'informatique :

🙋 Client = Application (site web, appli mobile)

🧑‍💼 Serveur = API

👨‍🍳 Cuisine = Serveur informatique / Base de données

📝 Commande = Requête

🍽️ Plat servi = Réponse (données)

Une API est donc un intermédiaire qui permet à deux logiciels de communiquer, sans que l'un ait besoin de connaître les détails internes de l'autre.

Mais dans la vraie vie, une requête ne se passe pas toujours bien... Découvrons pourquoi. ⬇️

👉 En API, cela s'appelle une erreur 401 – Unauthorized : vous n'êtes pas identifié ou autorisé à accéder à cette ressource.

📋 Les codes de statut HTTP à connaître

Chaque réponse d'API contient un code de statut qui indique si tout s'est bien passé ou non :

CodeSignificationAnalogie restaurant
200 OKTout s'est bien passéLe plat arrive à table 🍽️
400 Bad RequestLa demande est mal formuléeVous parlez une langue incompréhensible
401 UnauthorizedNon identifié / non autoriséAccès VIP refusé sans carte 🚫
404 Not FoundLa ressource n'existe pasLe plat n'est pas au menu
500 Internal Server ErrorProblème côté serveurLa cuisine est en feu 🔥

💡 Astuce : les codes commençant par 2 = succès, par 4 = erreur côté client (vous), par 5 = erreur côté serveur (l'API elle-même).

4xx = erreur du client
5xx = erreur du serveur

🏆 Félicitations !

Vous savez maintenant ce qu'est une API :

Une API est un intermédiaire qui permet à deux logiciels de communiquer, en s'envoyant des requêtes (demandes) et en recevant des réponses (données), via des endpoints (adresses), des méthodes (GET, POST, DELETE...), et des codes de statut qui indiquent si tout s'est bien passé (200) ou non (404, 401, 500...).
